`/nacho` 와 같은 도구를 호출하지만 **세션 컨텍스트를 본문으로 풀어쓰는 행위는 하지 않는다.**
민감 정보가 의도치 않게 노션·API 응답에 새 나가는 위험을 최소화하는 모드.

## 핵심 원칙

- **본문 자동 생성 금지** — 세션 대화·작업 결과를 요약해서 `--body` 에 넣지 않음
- **필드 추정 최소화** — 분류·프로젝트·상태도 사용자가 명령에 명시한 만큼만. 없으면 비움
- **session_id 만 자동** — `~/.cache/nacho/current-session` 에서 nacho 본체가 알아서 읽음 (LLM 무관, 로컬 처리)
- 사용자가 슬래시 줄에 인라인으로 적은 값만 사용

## 흐름

1. 사용자가 슬래시 줄에 적은 텍스트에서 다음만 추출:
   - **제목** — 가장 명확한 한 줄 (또는 "제목: X" 형태로 명시)
   - **분류 / 프로젝트 / 상태** — 사용자가 명시했을 때만 매핑 (DB 옵션과 정확 매칭). 추정 금지
   - **마감일 / 시작일** — 명시한 경우만
   - **링크** — 다음 우선순위로 결정:
     1. 사용자가 슬래시 줄에 명시한 URL (있으면 그대로)
     2. **같은 세션에서 직전에 `tako new` 또는 `/tako` 호출 결과로 출력된 Jira URL** — 세션 컨텍스트에서 추출해서 `--link <jira-url>` 로 전달
     3. 위 둘 다 없으면 `--link auto` 로 전달 (nacho 가 클립보드에서 URL 추출 시도)
   - **마감일** — 사용자가 마감일을 명시했으면 그대로 사용. **직전 tako 호출 출력에 duedate (`마감일`, `duedate`, `~YYYY-MM-DD` 등) 가 명확히 보였다면 그 값을 `--due-date YYYY-MM-DD` 로 명시적으로 전달**. (nacho 자체는 Jira 를 모름)
   - **본문** — 사용자가 "본문: ..." 또는 `--body` 로 명시했을 때만. 그 외엔 **빈 본문**
2. 미리보기를 채팅에 한 번 출력 (어떤 인자로 호출할지)
3. 사용자 확인 (`OK` / `수정해줘` / `취소`)
4. OK 면 `nacho new --yes --no-prompt --require-session ...` 실행.
   - `--no-prompt`: 대화형 질문 없이, **명시한 인자만 채우고 나머지는 빈 필드**
   - `--require-session`: session_id 필수 — Claude Code 세션 밖이면 에러 (정상). `--session-id` 는 명시 안 함 (nacho 가 hook 파일에서 읽음)

## 사용 예

```
/nacho-quick "정렬 깨짐 버그" Project A 운영
/nacho-quick 제목: 캐싱 도입 검토, 분류: 리팩토링, 마감: 다음주 금요일
/nacho-quick 새 todo: 회의록 정리
```

## 절대 하면 안 되는 것

- 세션 대화에서 본문 자동 추출·요약
- 회사 내부 시스템명·고객 실명·내부 URL 같은 식별자를 본인 판단으로 채워 넣기
- 사용자가 명시하지 않은 분류/프로젝트/상태를 LLM 이 추정해서 채우기
- DB 의 옵션 외 값을 임의로 만들어 넣기. nacho 가 거부함.

## 비고

- 본문이 필요하면 노션 페이지가 생성된 후 노션 GUI 에서 직접 작성. 또는 `본문: ...` 으로 명시.
- 세션 컨텍스트 자체는 어차피 매 Claude 호출마다 Anthropic API 로 전송되지만, 이 모드는 **추가로 본문 형태로 가공해서 응답에 포함시키지 않음** 으로써 의도 외 누출을 최소화.
- 더 강력한 보안: Claude Code 우회 (cmux 다른 패널에서 `nacho new --title ... --yes` 직접 호출).
