---
description: 업무 진행 일지에 한 줄 메모 추가 + 현황 요약 필드 갱신
---

세션에서 발생한 진행 상황을 노션 DB 행의 본문 `## 진행 일지` 섹션에 한 줄 append 하고,
같은 행의 **현황 요약 필드** (`config.yaml` 의 `fields.status_note` 매핑) 를 그 메모로 덮어쓴다.
한 눈에 보기용 DB list view 의 현황 요약 컬럼이 항상 최신 상태를 보여주게 됨.

## 흐름

1. 슬래시 줄에서 **업무 검색어** 추출 (반드시 명시)
2. 메모 텍스트 결정:
   - **사용자가 슬래시 줄에 메모 텍스트를 명시한 경우 그대로 사용 (LLM 가공 X)** — 보안 우선
   - 명시 안 된 경우에만 세션 컨텍스트의 최근 작업·결정을 **한 줄로** 요약
3. 미리보기를 채팅에 출력 — 어떤 명령으로 호출할지
4. 사용자 확인 (`OK` / `수정` / `취소`)
5. OK 면 `nacho note "<업무 검색어>" "<메모>"` 실행

## 사용 예

```
/nacho-note 큐레이션 스테이징 모니터링 후 다음주 배포 예정
/nacho-note 결제링크 만료 "PR 리뷰 대기"
/nacho-note 정렬 버그          ← 메모는 세션 컨텍스트에서 한 줄 요약
```

## 안전 가드

- 메모는 **한 줄, 60자 권장 · 100자 한계**. 길어지면 진행 일지 가독성 떨어지고 list view 컬럼이 잘림.
- 세션에 토큰·비밀번호·고객 실명 같은 민감 정보가 보이면 의식적으로 일반화하거나 제외.
- 업무 검색어가 여러 행에 매칭되면 nacho 자체가 사용자에게 번호 선택 prompt 띄움 — Claude 가 임의로 첫 결과를 고르지 말 것.

## 모드 구분 (메모 명시 여부)

| 호출 방식 | 메모 출처 | 보안도 |
|---|---|---|
| `/nacho-note <검색어> <메모>` | 사용자 명시 그대로 | 높음 — Claude 가공 X |
| `/nacho-note <검색어>` | 세션 컨텍스트에서 LLM 한 줄 요약 | 중 — 가공 발생 |

민감한 진행 상황이면 **검색어 + 메모 둘 다 명시**하는 형태 권장.

## 셸 직접 호출 (Claude 우회 — 최대 보안)

Claude 세션 거치지 않고 직접:
```bash
nacho note "큐레이션" "스테이징 모니터링 후 배포 예정"
```
